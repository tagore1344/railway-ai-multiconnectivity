# AI-Powered Multi-Connectivity Edge Gateway for High-Mobility Railway Wi-Fi

## Abstract

This work presents a simulation-driven architecture for a railway edge gateway that combines multiple heterogeneous backhaul links for passenger connectivity. The prototype evolves from static multi-link selection to adaptive monitoring, train-mobility-aware link scoring, automated failover, randomized connectivity conditions, and machine-learning-assisted prediction of the next preferred network. In the current simulation dataset, a Random Forest predictor achieved 99.24% next-network classification accuracy on 132 observations from 12 previously unseen randomized seeds. This figure is simulation evidence only and does not establish real-world cellular prediction accuracy. A packet-level bonding prototype is introduced as the next stage to measure striping, reordering, duplicate handling, and effective goodput under heterogeneous path delays.

## 1. Introduction

High-speed railway connectivity changes rapidly because radio conditions, cell coverage, path latency, and backhaul availability vary with train position and motion. A gateway that selects only one network may experience avoidable service degradation even when another path remains usable. The project investigates a multi-connectivity edge gateway that monitors multiple networks, assigns passenger traffic dynamically, anticipates upcoming network changes, and eventually aggregates several paths at packet level.

## 2. System Architecture

The architecture contains link monitoring, mobility/route state estimation, adaptive decision control, predictive inference, and multi-link transport. The current simulation models three heterogeneous networks with nominal capacities of 30, 20, and 15 Mbps and different path delays. The controller evaluates link quality, latency, packet-loss estimate, capacity, and current load.

## 3. Methodology

V1 established a three-link baseline. V2 introduced capacity-aware load balancing. V3 added failover. V4 introduced train movement. V5.1 corrected traffic measurement and added time-series logging. V6 introduced composite adaptive scoring. V7 generated 840 observations from multiple scenario combinations. V8 established an ML baseline. V8.1 changed the target to the next controller decision. V8.2 added controlled random channel variation and evaluated generalization on unseen seeds.

The V8.2 dataset contains 720 observations from 60 independent randomized seeds. After constructing a next-decision target, 660 rows remain usable. Training uses 48 seeds and 528 samples; testing uses 12 unseen seeds and 132 samples.

A Random Forest classifier predicts the network selected at the next controller observation using current train position, current link quality, latency, packet-loss estimate, and link load. The current selected network and controller-generated score fields are excluded from the V8.2 predictor to reduce direct decision leakage.

## 4. Results

The V8.2 predictor obtained 99.24% accuracy on the unseen-seed test set. Class-level F1 scores were 1.00 for network 1, 0.99 for network 2, and 0.99 for network 3. Train position was the most important feature, followed by network load and quality/loss variables.

These results should be interpreted as evidence that the modeled state variables contain predictive information under the present synthetic mobility/channel model. They should not be presented as measured real-world railway-cellular performance.

## 5. Reactive vs Predictive Evaluation

The V9 framework compares a reactive policy that waits for the current controller decision with a predictive policy that attempts to prepare for the next network transition. The available V8.2 traces support an offline controller-score comparison, but they do not provide per-interval throughput. Therefore the current V9 offline score is a utility proxy rather than a throughput result.

## 6. Multi-Link Bonding

The V10 stage estimates the capacity benefit of using multiple simultaneously reachable paths. The V12 stage moves toward packet-level striping by assigning sequence numbers, selecting paths with weights, handling different path delays, and reassembling packets at the receiver. This stage must be validated with actual simulated goodput before claims about true speed aggregation are made.

## 7. Limitations

The current evidence is simulation-based. The channel variation model is synthetic, path capacities and delays are simplified, and the ML target is generated by the same simulation family used for the inputs. The packet-bonding prototype is not a production MPTCP, MPQUIC, or SD-WAN implementation.

## 8. Future Work

1. Validate the V12 ns-3 packet-level prototype.
2. Add packet loss and retransmission across alternate paths.
3. Integrate the predictive scheduler with packet striping.
4. Add route/digital-twin features and cell-tower intelligence.
5. Evaluate weather-aware connectivity as an experiment.
6. Build a hardware gateway with multiple cellular modems and local edge inference.
7. Collect real railway measurements and recalibrate the simulation/model.

## 9. Reproducibility

The GitHub repository contains historical source stages, simulation datasets, ML scripts, evaluation scripts, and experiment documentation. Every result should be labeled by simulation version, seed split, and whether the metric is measured, simulated, or modeled.
